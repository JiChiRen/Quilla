# 编码规范

**中文** · [English](coding-guidelines.md)

Quilla 对**自身编写的代码**以 **MISRA C:2012** 作为编码规范。本页说明这条规范在本项目里意味着什么、不意味着什么，以及边界在哪里 —— 便于集成方判断树内哪些部分受规范约束、哪些不受。

## 1. 这份说明是什么，不是什么

**是**：对本仓库自有源码所遵循的编码规则及其覆盖范围的陈述。

**不是**：一份"Quilla 符合 MISRA C:2012"的声明，也不构成任何安全或认证主张。本项目在本公开仓库中**不提供**合规声明、偏差登记册或工具鉴定记录。下述规则是作为工程纪律执行的，覆盖是部分的，且未为对外发布做过审计。

## 2. 范围

### 纳入

本项目自有代码：内核与系统服务（`os/sys/`、`os/services/`）、Quilla 自有的 Arm 与 RISC-V 层（`arch/cpu/` 下带 `quilla-` 前缀的实现），以及 `user/<mcu>/` 下的各 MCU 工程树。

### 排除，且是刻意的

| 来源 | 理由 |
|---|---|
| 上游 Contiki-NG（`os/net/**`、`arch/dev/**` 等继承目录） | 保持合并干净：就地改写会在每次上游合并时重做。按既有软件处理。 |
| CMSIS 与厂商 HAL/SDK（PUYA、GigaDevice、WCH） | 按既有软件处理；就地修改会破坏器件库的可追溯性。 |
| 构建、测试与核查脚本（Python、shell） | 不属于随固件发布的软件。 |

排除必须写明 —— **沉默排除**与"已检查"在报告里长得一模一样。

## 3. 塑造代码的几条规则

阅读代码时最容易看到的几条：

- **禁止动态内存分配**。`malloc`/`free` 一类接口在链接层被移除，分配入口是死桩；以栈水印检查替代堆使用。
- **禁止递归**。调用深度有界，静态栈定尺才有意义。
- **统一使用定宽类型**（`stdint.h`），不依赖隐式整型提升的宽度。
- **安全相关路径的控制流单一且显式** —— 尤其启动交接顺序（清 NVIC → 停 DMA → 设 VTOR/MSP → 开中断 → 跳转）是固定且顺序相关的。
- **写入后校验**。Flash 编程后逐字节读回比对，因为厂商 HAL 不报"非擦除位"类错误。
- **失败路径显式**。安全检查是失败即停：未通过验签的镜像不启动。

## 4. 一致性如何推进

每次改动：对照规范做人工评审，并对适合文本与 AST 匹配的规则子集做机检（例如禁用构造、缺失 `default` 分支、switch 贯穿等）。

**尚未具备、因此不作宣称**的部分：覆盖完整规则集的已鉴定静态分析器、持续维护的偏差登记册、独立的评审角色。缺这些支撑时给出合规声明是没有依据的，所以不给。

## 5. 若你基于本代码衍生

- 请对**你自己编写的代码**执行同样规范；上面的纳入边界描述的是本仓库的作者归属，不代表继承代码已被评审。
- 尽量不改动上游与厂商目录 —— 这个性质正是合并成本低的原因。
- 不要把"没有合规声明"读成缺陷清单，它就是当前真实状态。
